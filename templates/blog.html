Explore methods used to enhance Land Surface Temperature (LST) resolution, identify urban hotspots, and evaluate algorithmic accuracy in geospatial analysis.

📘 Introduction

Urban Heat Islands and LST Importance
With increasing urbanization and climate change, urban heat islands (UHIs) have become a critical environmental issue, particularly in Indian cities, where summer temperatures frequently exceed 45°C. The Urban Heat Island effect arises due to the replacement of natural landscapes with heat-absorbing infrastructure such as asphalt, concrete, and metal, which retain more heat compared to vegetated surfaces. This phenomenon leads to higher ambient temperatures in urban areas, exacerbating the impact of heatwaves, increasing energy consumption for cooling, and posing serious health risks, particularly for vulnerable populations.

One of the most effective ways to assess UHI intensity is through Land Surface Temperature (LST) analysis, which provides insights into urban thermal patterns. Several studies have examined the relationship between urbanization, land use changes, and LST variations in Indian cities. However, existing research often focuses on individual cities rather than a comprehensive multi-city comparison. Moreover, while satellite-based LST estimation has been widely used, there is a need for a more systematic, automated approach to analyze urban heat patterns over time and across multiple cities.

1.1. Significance of the Study
This study aims to address these gaps by:
  1. Mapping urban heat island hotspots in 20 major Indian cities using satellite-based geospatial analysis.
  2. Applying statistical methods such as thresholding, Urban Thermal Field Variance Index (UTFVI), and spatial statistical analysis (Getis-Ord Gi*) to identify and assess heat-prone areas.
  3. Conducting a temporal analysis to examine how LST patterns have evolved over the past decade.
  4. Providing automated data processing tools to streamline heat island analysis across multiple urban areas.
By integrating Google Earth Engine (GEE) for large-scale data processing, this study contributes to urban planning and climate adaptation strategies by providing policymakers with critical insights for mitigating heat-related risks through urban design interventions such as green spaces, reflective surfaces, and heat-resistant infrastructure.

📘 Methodology

🛰️ Google Earth Engine API Setup

  1. Enable the API: Visit the Google Cloud Console, create/select a project, and enable the Earth Engine API from the API library.
  2. Create Service Account: In “IAM & Admin,” create a service account. Assign the Viewer role or skip roles if unused.
  3. Generate Key: Create a new key (JSON) for the service account and download it.
  4. Grant Earth Engine Access: Go to Earth Engine Permissions and add the service account email.
  5. Install API: In your environment, run:
    pip install earthengine-api
  6. Initialize in Python:
    import ee
credentials = ee.ServiceAccountCredentials(
    'your-service-account@your-project.iam.gserviceaccount.com',
    'path/to/credentials.json'
)
ee.Initialize(credentials)

📅 Date Range Configuration

The dashboard auto-computes the last two full months based on the current date using datetime and relativedelta. It prepares start/end dates to fetch and process temperature data per city. Each city’s output is stored in structured folders named by city and month.

🗺️ Google Earth Engine Setup and Shapefile Handling

  • Authentication: Earth Engine is initialized via a service account and JSON key.
  • Shapefile Extraction: Each city’s boundary is stored as a zipped shapefile. It's extracted temporarily.
  • Loading Geometry: The shapefile is loaded with GeoPandas, geometries are merged via union_all(), and converted to ee.Geometry for spatial analysis.

🌡️ Land Surface Temperature (LST) Extraction and Processing

  • LST from Landsat: Landsat 8 & 9 data (ST_B10 band) is used. It's scaled to Celsius and cloud/cloud-shadow pixels are masked using QA flags.
  • Monthly Composites: For each month, imagery is filtered by city geometry and date range. A median composite is created from clear pixels.
  • Ward-Level LST: Each ward's average LST is calculated. Wards with no clear pixels are flagged as cloudy. Cloud presence is assessed using unmasked pixel checks.
  • Data Storage:
    • GeoJSON with each ward's LST and cloud cover
    • Top 10 hottest wards (by LST) in JSON
    • Min/Max LST values for visualization scaling

📊 Yearly Average Temperature (ERA5 - Meteoblue Style)

  • Source: ERA5-Land Hourly (2m air temp) data via GEE, from 1980 to previous year
  • Processing: For each year:
    • Daily min and max are calculated
    • Daily average: (Tmin + Tmax) / 2, converted from Kelvin to Celsius
    • Yearly mean temperature is computed over the city geometry
  • Storage: Each year’s mean value is saved in JSON format for visual comparison

🗺️ LST Visualization Tiles (2025)

  • Cloud Filtering: Landsat 8/9 images are filtered to exclude dilated clouds, cirrus, cloud shadows, and snow using QA_PIXEL bits.
  • LST Calculation: ST_B10 is scaled to °C. Only cloud-free pixels are used for a monthly median composite.
  • Visualization Layers:
    • City-wide mean LST is computed
    • A threshold mask hides very low values
    • A cloud mask layer is generated separately
  • Tile URLs: LST and cloud layers are converted into dynamic tile URLs for frontend map rendering.
  • Monthly JSON: For each month:
    • Start & end dates
    • Average LST
    • Threshold used
    • LST tile URL
    • Cloud tile URL

📘 Understanding the LST Extraction Logic

Detailed Breakdown of Google Earth Engine Computations
3.1 How Land Surface Temperature (LST) is Calculated
We compute LST using the thermal infrared band (Band 10) of the Landsat 8 Collection 2 Level-2 data. The equation used in our script is:

LST = ST_B10 * 0.00341802 + 149.0 - 273.15

Here's what each component means:
  • ST_B10: This is the surface temperature band provided by Landsat in scaled form (scale factor = 0.00341802 and offset = 149.0).
  • Multiplying by 0.00341802 converts the digital number to top-of-atmosphere brightness temperature in Kelvin.
  • Adding 149.0 is the radiometric offset provided in Landsat's metadata.
  • Subtracting 273.15 converts the temperature from Kelvin to Celsius.
The final result is a new image where each pixel represents the land surface temperature in degrees Celsius.

3.2 Why We Take Median of the Image Collection
We use collection.median() to compute the median LST value across all cloud-free observations during the specified month. This ensures that transient weather conditions (e.g., cloud cover or anomalies) don’t distort the monthly average. Median is preferred over mean as it is more robust to outliers.

3.3 Averaging LST Over Administrative Wards
To derive average LST values at the ward level, each ward polygon is iterated, and the LST image is reduced using: image.reduceRegion(ee.Reducer.mean(), geometry, scale=1000).
- The mean reducer gives the average LST within each ward. - Scale of 1000 meters is chosen to match the MODIS resolution and reduce computation time, as Landsat data is more granular (30m).

3.4 Classification Into Color Classes
Once LST values are extracted for each ward, we divide them into 5 classes based on quantiles (20%, 40%, 60%, 80%). Each class is assigned a color code for visualization.
This classification helps in clearly identifying high-temperature zones and comparing across wards.

3.5 Top 10 Hottest Wards
We sort the wards in descending order of their average LST values and extract the top 10. These are stored separately for use in dashboards and analytics.

3.6 Annual and Monthly Averages
  • Landsat (2013-2024): We compute yearly average LST using median composite images for the entire year.
  • MODIS (2000-2025): Monthly averages are calculated using MOD11A2 8-day composites aggregated to the monthly scale. The values are converted using LST * 0.02 - 273.15 to bring them to Celsius.
These temporal datasets help in understanding LST trends over time.

3.7 Masking Hotspots for Visualization
To highlight unusually hot areas, we use a masking threshold: masked_image = median_image.updateMask(median_image.gt(avg_lst * 1.2))
- This means only pixels with LST > 120% of average citywide LST are retained. - It allows us to visually highlight hotspots on a map.

3.8 Serving Visual Layers on the Web
Using getMapId() and tile_url, we export a visualization tile layer styled using: 
{
      min: 15,
      max: 45,
      palette: ['blue', 'cyan', 'green', 'yellow', 'red']
    }
This visual layer is loaded dynamically on the city dashboard using Leaflet.js.

3.9 Summary
The entire pipeline is implemented in Python with Google Earth Engine’s Python API. From raw satellite data to downloadable GeoJSONs and interactive visualizations, our methodology automates LST extraction for Indian cities at both monthly and annual scales.
